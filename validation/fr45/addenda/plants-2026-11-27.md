Dated 27 November 2026. Drafted by FR-45's builder for TABLE.md §8.1 and §14.1 item 4. A reviewer who is not the
builder confirmed each patch against `src/` [N1], as below. The lead hashes the patches before any registered run.

## Changed inputs (`plant.inputs_changed`)

Only P2 is planted by declaration. Every other plant's `inputs_changed` is empty: its patch is code, outside
`definition` (§4), and the patch review covers it (N1).

| Run | Inputs key path | Value | Where it sits in `definition` |
| --- | --- | --- | --- |
| `W1p-P2` | `populations[id=matrix_L1].k_off` | 0.15 (matrix_L2's registered value) | `model.operators[law=cells.operator.site_occupancy@1].populations[id=matrix_L1].dissociation_rate_per_s` |
| `W1p-P2` | `populations[id=matrix_L2].k_off` | 0.9 (matrix_L1's registered value) | `model.operators[law=cells.operator.site_occupancy@1].populations[id=matrix_L2].dissociation_rate_per_s` |

- **The values** are the expected-inputs file's `plant_inputs_changed` (§12.2). The honest W1p's parse-only pass has
  matrix_L1's `dissociation_rate_per_s` 0.9 and matrix_L2's 0.15 at those paths. `plants/p2.py` crosses the two in
  `declare`, and the driver records the two paths.
- **The judge** applies them to the honest run's `definition` at these paths before comparing the plant run's
  (`judge.py`: `B6_DEFINITION`, `_definition_with`). Any other difference is a fault of the run's identity (§4,
  §11.1 item 13).

## Patch files for the lead's hashes

These are the patches the registered plant runs take (`validation/fr45/plants/`), one per row of CRITERIA:119-129.
The driver imports the module, applies its `declare` to the inputs, and calls its `apply()` in the plant run's own
process (§8.1).

| File | Plant | What it changes (its `CHANGE`) |
| --- | --- | --- |
| `validation/fr45/plants/__init__.py` | (all) | `same`: the honest inputs, unchanged, for every plant but P2 |
| `validation/fr45/plants/p1.py` | P1 | `member_free_sites`: each population's free sites S_s − B_b, as if alone on its set |
| `validation/fr45/plants/p2.py` | P2 | inputs: the two populations' `k_off` crossed (planted by declaration) |
| `validation/fr45/plants/p3.py` | P3 | `site_lattice_terms`: each member's free sites S_s − B_b in G_site, in the booking and the ledger |
| `validation/fr45/plants/p4.py` | P4 | `stage_loads`: L_R per population, not summed over its set, in the step and the host report |
| `validation/fr45/plants/p5.py` | P5 | `apply_events`: every B facing the washed node scaled by (1 − f), R unchanged |
| `validation/fr45/plants/p6.py` | P6 | `node_booking`: each set's ΔG_R counted once per ligand pool |
| `validation/fr45/plants/p7.py` | P7 | `set_free_change`: dR from each set's first population only |
| `validation/fr45/plants/p8.py` | P8 | `moiety_residuals`: R_s + B_b − S_s per population, summed onto its set |
| `validation/fr45/plants/p9.py` | P9 | `occupied_fraction`: B_b / (B_b + R_s) |

`plants/INVENTED_p3_dissipation.py` and `plants/INVENTED_p7_host.py` are development-only. They exercise the
dissipation check and a host check on invented worlds, and no registered run takes them.

## Confirmed at the review (27 November 2026) [N1]

- **Every patch** changes only what its row's mechanism names, and every exception and check name it can raise is
  in the refusal mapping.
- **P2's paths** are as above.
- **P3 is faithful:** S_s − B_b in G_site, in both the booking and the ledger. So its catch is C3b or the
  dissipation check, never the energy ledger (§8.2).
- **P5 acts as its row says:** every B facing the washed node scaled by (1 − f), R unchanged, wherever the engine
  implements the wash.
