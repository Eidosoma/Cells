# Explicit native membrane-layout bridge to component initialization

This separate prefix preserves initialization02, layout01 and metric01/02.
Its runtime sources come from the immutable initialization02 and layout01
bundles, keeping active mechanics, calcium and catalog work outside this packet.
No qualification of those parents is inherited.

The bridge captures a complete original initializer boundary together with the
six-column layout snapshot. Supplied captures and pinned native captures have
separate observation kinds. Both retain the full original owner/caches and all
six membrane columns. Shared cell/membrane axes, membrane owners, midpoints and
six-column bytes must match between the two captures. The layout's original
stride metadata remains attached; the initializer's immutable array copy need
not reproduce source aliases or strides. No owner inference or coordinate
reconstruction occurs in production.

Only the named `native_six_to_midpoint_normal_xy@1` conversion is accepted. It
selects `[mid_x,mid_y,nx,ny]` by exact typed bytes. The result becomes a separately
sealed **supplied** boundary, with explicit original-boundary, original-layout,
pair and view identities. It cannot masquerade as a native capture. Every other
owner entry, hot cache, exclusion and upstream evidence remains unchanged.
Tangents stay in the full parent and are not geometrically qualified.

The unchanged initializer's common owner checks run before a prepared request
is returned. They validate supplied operators/state, branch policies, required
stores, publication/coefficient ownership and cache epochs. The full presence
inventory is retained, including optional missing stores. Common readiness
does not imply that serializer or optional calcium admission has completed.
The request explicitly records both as pending. Revalidation rebuilds the
projection and common readiness before consumption, rejecting resealed changes
to projections, readiness or gates.

The component entry invokes the unchanged initializer handoff once. That path
retains calcium refusal policies, restores the actual hot cache, verifies its
round trip and executes the existing single field bootstrap. It calls no cold
initializer, native dynamics, seed, loop step or mechanics attachment. The
wrapper records the actual field request before evaluation and the complete
held receipt before checking scope and hot-cache preservation. Its returned
component receipt remains attached to the original paired owners.

Source correspondence follows the native load and prebootstrap calls, actual
six-column producer, shared-store checks and cache serializer. `Egj` is written
by `update_gj`; its presence and epoch at the declared seam must be observed
from actual loaded owners. This bridge does not fill it with a zero. Native
class/hash observations do not prove that the full seed/init/load chain ran.
Matching a supplied binding likewise establishes no physical mesh origin.

The independent reference imports only standard-library code and the held
standalone layout checker. It reads lossless typed sidecars, verifies full
parent retention, mixed units/column roles, exact projection bytes and all
unmodified stores. It independently scans hot-cache owner axes and publication,
coefficient and ionic boundary epochs, checks provenance/seals and confirms the
closed gates. It runs no field solver or native code and earns no new numerical
accuracy credit. Existing component equations and budgets remain unchanged.

Prospective positive cases use explicitly supplied six-column stores on the
held field, polarized, warm-owner and calcium specimens, plus a strided storage
case. Their setup may use the existing manufactured cold fixture after a future
authorized launch; the bridge itself must preserve the hot owners without a
reset. These are not actual native-generated meshes or seed/init trajectories.
Controls cover absent/malformed layouts and owner rows, changed paired stores,
unready hot caches, source policies/epochs, optional calcium admission before
hydration, resealing, independent corruption and caller-buffer independence.

checker children, plus one Root finalizer:55 distinct process units. Only42

original pytest trees and must not be recreated with independent replays.

All new calls require declared inputs and preserve full original arrays,
conversion requests/outputs, readiness returns, component inputs/outputs and
failure partials as typed sidecars before gates. Process summaries must link
those sidecars instead of embedding large payloads. Chief/Root owns resource
guarding, later review, launch, finalization and `PROGRESS.md`.

immutable copying only. No scientific import, fixture construction, adapter,

is performed. Physical geometry, tangent qualification, native history and
